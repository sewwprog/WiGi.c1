# StoneLand II — Minecraft portal

Адаптивний сайт в Minecraft-стилі: **Головна / Новини / Галерея / Спільнота / Кабінет / Адмінпанель**.
IP сервера не публікується.

## Status — live Supabase connected

- Окремий Supabase-проєкт: https://supabase.com/dashboard/project/spfpwknvesclrmjcbwce
- `config.js` уже містить публічні URL і publishable key.
- Створено таблиці `sl2_profiles`, `sl2_admins`, `sl2_posts`, `sl2_photos`.
- Увімкнено RLS та bucket `sl2-gallery`.
- Застосовано обмеження частоти реєстрацій (`sl2_signup_quota`).
- Розгорнуто серверну Edge Function `sl2-register` (`verify_jwt=false`, тому що реєстрація публічна).
- Реєстрація через серверну функцію використовує `auth.admin.createUser` з `email_confirm: true`: **не треба вимикати Confirm email**.
- Гравці вводять тільки **логін і пароль**, без реальної пошти; позаду використовується внутрішній логін `nickname@stoneland.invalid`.
- Supabase Auth сам зберігає хеші паролів та створює сесії.
- Гості можуть читати новини/галерею, але не можуть писати чи видаляти їх.
- `sl2_admins` обмежує права адміністратора на рівні бази, а не тільки JavaScript.

## Перший власник / адміністратор

Початкова реєстрація `SeWapro` відбувається **на самому сайті** через спеціальний одноразовий код активації. Не потрібно вручну створювати Auth user в Supabase Dashboard.

1. Відкрий сайт, обери **Кабінет → Реєстрація**.
2. Уведи логін `SeWapro`. З'явиться поле одноразового коду.
3. Устав приватний код активації, отриманий окремо від адміністратора проєкту. **Код не зберігається в GitHub і його не можна публікувати.**
4. Створи **новий унікальний пароль із 12+ символів**, підтверди його й натисни Реєстрація.
5. Supabase одноразово перевірить токен, підтвердить акаунт і додасть користувача до `sl2_admins` у тій самій транзакції, після чого сайт відкриє панель адміністратора.
6. Надалі для входу потрібні тільки `SeWapro` і твій пароль. Код повторно не потрібен і не працюватиме після використання.

**Безпека:** не використовуй пароль, який раніше писав у чаті. Якщо код загублено або прострочено, власник Supabase-проєкту може видати новий лише через довірений доступ до бази даних. Код не можна давати іншим людям.

## Функції адмінпанелі

- Публікація і видалення новин.
- Завантаження скріншотів JPEG, PNG, WebP до 5 МБ та їх видалення.
- Користувачі без прав адміністратора не можуть змінювати публічні дані навіть прямими запитами до API.

## Публікація

У GitHub https://github.com/sewwprog/stoneland-2 → Settings → Pages → Deploy from a branch → `main` → `/ (root)`.

Очікувана адреса після активації: https://sewwprog.github.io/stoneland-2/

## Файли

- `index.html`, `styles.css`, `app.js` — клієнтська частина.
- `config.js` — публічні параметри підключення (не пароль і не secret key).
- `supabase/schema.sql` — базова схема.
- `supabase/migrations/01_signup_throttle.sql` — серверне обмеження запитів.
- `supabase/migrations/02_admin_activation.sql` — одноразовий код власника.
- `supabase/functions/sl2-register/index.ts` — серверне створення підтверджених Auth-користувачів без електронних листів.
- `assets/` — оригінальні піксельні ілюстрації.

### Якщо переносиш на інший Supabase
На **новому порожньому** проєкті застосуй SQL послідовно: `schema.sql`, `migrations/01_signup_throttle.sql`, `migrations/02_admin_activation.sql`, створюй секретний інвайт у SQL Editor та розгорни Edge Function. У поточному проєкті всі три міграції **вже застосовано**, повторювати не треба.

Без реальної пошти автоматичне email-відновлення пароля недоступне; за потреби доступ відновлює власник Supabase-проєкту.
