# StoneLand II — Minecraft портал

Мінімалістичний сайт Minecraft-сервера з окремими екранами:
**Головна, Новини, Галерея, Спільнота, Кабінет, Адмінпанель**.
IP-адреса сервера ніде не вказана. Пошта не запитується.

## Що вже готово
- Повністю новий адаптивний UI у темно-зеленій піксельній стилістиці
- Перемикання екранів без перезавантаження (за hash URL)
- Форми входу/реєстрації **за логіном і паролем**
- Supabase Auth: автоматичне збереження сесії; паролі не зберігаються в JS
- Публічні новини, фото та список зареєстрованих нікнеймів
- Адмінпанель: створення/видалення новин, завантаження/видалення фото
- Таблиці з Row Level Security (RLS), Storage-політики з обмеженнями на admin UID
- Фільтрація імен файлів, форматів фото (PNG/JPEG/WebP, до 5 МБ)
- Чисті JavaScript/HTML/CSS без збірки й бекенду на GitHub Pages

## ВАЖЛИВО: Supabase поки не активований
Параметри `config.js` порожні навмисно: у власника є кілька Supabase-проєктів,
але жоден не визначений як база StoneLand II. **Не використовуйте існуючу базу іншої програми.**
До створення окремого проєкту працюють зовнішній вигляд, розділи та навігація;
реєстрація, вхід, новини, фотозавантаження потребують активації Supabase.

## Підключення нового Supabase-проєкту

1. Створи **окремий** Supabase-проєкт `stoneland-2` у своїй організації.
2. Відкрий у Supabase **Authentication → Users → Add user**.
   - Email (використовується **тільки всередині** Supabase для авторизації): `sewapro@stoneland.invalid`.
   - У полі пароля вкажи **новий сильний секрет**, який ніде не публікувався.
   - Познач email як підтверджений / Auto Confirm. Це внутрішній технічний ідентифікатор, реальної пошти немає.
   - **Створи адміна ДО виконання SQL нижче!** SQL навмисно блокує пізнішу реєстрацію цього зарезервованого логіна.
3. Відкрий **SQL Editor** у новому Supabase-проєкті та виконай весь `supabase/schema.sql`.
   Схема створює `sl2_profiles`, `sl2_admins`, `sl2_posts`, `sl2_photos`,
   обмеження доступу, автопрофілі та bucket `sl2-gallery`. Вона також прив'язує
   раніше створеного `SeWapro` до таблиці адміністраторів за конкретним Auth UUID.
4. Відкрий **Authentication → Providers → Email** і вимкни **Confirm email**.
   Звичайні користувачі не вводять пошту; під капотом їхні логіни перетворюються
   на внутрішні ідентифікатори на кшталт `nick@stoneland.invalid`, які
   використовує Supabase Auth для перевірки пароля. Повідомлення на них не відправляються.
5. Відкрий **Project Settings → API Keys** і скопіюй **publishable key**
   (`sb_publishable_...`). Також скопіюй **Project URL** (`https://....supabase.co`).
6. У `config.js` встанови:
   ```js
   window.STONELAND_CONFIG = {
     supabaseUrl: "https://YOUR_PROJECT.supabase.co",
     supabaseKey: "sb_publishable_YOUR_KEY"
   };
   ```
   Публічний publishable key можна розміщувати в браузері **лише** разом із коректними RLS-політиками.
   **Ніколи** не публікуй service_role, sb_secret_ ключі або паролі.
7. У **Settings → Pages** свого GitHub-репозиторію вибери **Deploy from branch → main → / (root)**.

## Адмінпанель
Вхід у сайт: логін `SeWapro`, пароль з Supabase Auth, створений на кроці 2.
Адмінвизначення серверне: тільки UUID із `public.sl2_admins` може змінювати
таблиці чи файли; зміна нікнейму / JS / URL не дає прав.

**Примітка безпеки:** пароль, уже написаний у відкритому чаті, не слід повторно
використовувати для адміністративного акаунта. Зміни його на новий у Supabase.
Якщо забув пароль від акаунта без пошти, автоматичного email-reset немає:
власник проєкту має відновити доступ через Supabase Dashboard.

## Структура
- `index.html` — окремі екрани та форми
- `styles.css` — Minecraft-inspired адаптивний дизайн
- `app.js` — авторизація, навігація, отримання/керування даними
- `config.js` — тільки публічна конфігурація Supabase
- `supabase/schema.sql` — таблиці, RLS, профілі, Storage
- `assets/stone-icon.svg`, `assets/pixel-world.svg` — оригінальна піксельна графіка

## Перевірка після налаштування
1. Зареєструй звичайний тестовий акаунт за логіном і паролем.
2. Перезавантаж сторінку — сесія має зберегтися.
3. Перевір, що звичайний акаунт **не бачить** адмінпанель і не може
   додавати/видаляти новини через API.
4. Увійди як `SeWapro` з новим паролем, додай новину та фото.
5. Перевір, що новина і фото доступні без входу, а інші користувачі не можуть змінити їх.
